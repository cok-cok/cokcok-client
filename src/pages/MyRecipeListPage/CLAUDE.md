# my recipelist page

## 1. 페이지 설명

로그인한 사용자가 자신이 작성한 레시피 목록을 확인하고 관리하는 페이지.

앱 진입 후 첫 화면이며,
레시피 작성 / 상세 조회로 이동하는 허브 역할을 한다.

## 2. 진입 경로

- 로그인 성공 시
- 앱 실행 시 (자동 로그인 상태)
- 레시피 생성/수정/삭제 이후

## 3. 이탈 경로

| 상황                  | 이동               |
| --------------------- | ------------------ |
| 레시피 클릭           | 레시피 상세 페이지 |
| 레시피 작성 버튼 클릭 | 레시피 작성 페이지 |
| 마이페이지 버튼 클릭  | 마이페이지         |
| 뒤로가기 (Android)    | 앱 종료            |

## 4. 화면 구성

| UI 요소          | 설명                                                                    | 필수 여부 | 비고 |

| 레시피 카드      | 대표 이미지(없으면 기본 이미지), 제목, 태그<br>설명, 소요 시간, 몇 인분 | Y         |      |

## 5. 사용자 시나리오

1. 사용자가 로그인한다.
2. 내 레시피 리스트 페이지에 진입한다.
3. 서버에서 레시피 목록을 조회한다.
4. 레시피 목록을 화면에 표시한다.
5. 사용자가 레시피를 클릭한다.
   → 레시피 상세 페이지로 이동
6. 사용자가 레시피 작성 버튼을 클릭한다.
   → 레시피 작성 페이지로 이동

## 7. API 명세

### 내 레시피 목록 조회

| 항목     | 내용                |
| -------- | ------------------- |
| API 목적 | 내 레시피 목록 조회 |
| Method   | GET                 |
| Endpoint | /api/recipes/my     |

**Request**

```json
{
  "page": 1,
  "size": 20
}
```

**Response (성공)**

```json
{
  "nextPage": "number | null",
  "recipes": [
    {
      "id": 1,
      "title": "string",
      "thumbnailUrl": "string",
      "description": "string",
      "tags": ["string"],
      "cookTime": {
        "hour": "number",
        "minute": "number"
      },
      "portion": "number"
    }
  ]
}
```

> **`nextPage`** (필수) — 다음에 요청할 페이지 번호. 더 가져올 게 없으면 `null`. 인피니티 스크롤이 prefetch 시점과 끝 메시지 노출 시점을 분기하는 데 사용. 클라이언트는 응답의 `nextPage`를 그대로 다음 `loadMore` 요청에 사용 — 페이지 번호 계산 책임을 서버가 가져 일관됨. `null` 응답을 받기 전까지는 페이지가 더 있다고 간주.

**Response (실패)**

```json
{
  "message": "인증이 필요합니다."
}
```
